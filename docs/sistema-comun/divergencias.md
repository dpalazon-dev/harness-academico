## Arranque en Windows

El ticket 04 añade `npm run desktop:dist:win` en `package.json` y su operador en `scripts/desktop-dist-win.mjs`. En `work/compilado` prepara el standalone, comprueba el servidor con Electron, empaqueta con NSIS y prueba el resultado. El commit queda en `resources/server/standalone/build-commit.txt`. La configuración de identidad y el destino NSIS del fork siguen definidos en `electron-builder.yml`.

`npm run desktop:dev` usa sintaxis POSIX para variables de entorno y no funciona en `cmd`. En Windows:

```bash
LH_DATA_DIR=<carpeta de datos> npm run dev
LH_DEV_URL=http://localhost:3000 LH_DATA_DIR=<carpeta de datos> npx electron .
```

Si `npm ci` no deja `node_modules/electron/dist/electron.exe`, ejecutar `node node_modules/electron/install.js`.

**Parar el servidor de desarrollo entero.** Matar solo el proceso que escucha en el puerto 3000 deja vivo el `next dev` padre. Esos procesos huérfanos bloquean `dist/plugin-authoring` (el siguiente arranque falla con `EPERM`) y, si conviven con un servidor nuevo, escriben en la misma caché `.next` y provocan un bucle de recargas al abrir una página. Hay que cerrar todos los procesos de Node del worktree, por ejemplo en PowerShell:

```powershell
Get-CimInstance Win32_Process -Filter "Name='node.exe'" | Where-Object { $_.CommandLine -match 'sistema-comun' } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

Los cambios de un plugin de núcleo exigen reiniciar: no hay recarga en caliente de plugins.

## Cuadernos: 12h, dibujos con Mermaid (20-nov-2026)

- **Seguridad del renderizador.** El Mermaid lo escribe el modelo y se pinta en el navegador de David. `mermaidConfig` ya fija `securityLevel: "strict"` (HTML de las etiquetas codificado, sin `click` ejecutable) y sirve para contenido del modelo: no se debilita.
